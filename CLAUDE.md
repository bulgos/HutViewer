# CLAUDE.md

## Git

- Clear, concise branch names that say what the change is (e.g. `fix-mobile-legend`).
- Clear, concise, atomic commits: one change each, that builds and passes lint on its own.
- Commits and pull requests: a title only, no description, no attribution lines.

## Plans

- Name the branch the plan is built on.
- Estimate how many lines of code will be added or changed.
- Success and failure criteria: how we know it worked, and what counts as it not working.
